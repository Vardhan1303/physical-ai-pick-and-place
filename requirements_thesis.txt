# Dependency list — ArUco-Guided Point-Prompted Object Segmentation project
# (the robosuite-based thesis pipeline; separate from requirements.txt,
# which belongs to the older raw-MuJoCo-XML pick-and-place demo in this
# same repo — see the note below on why these can't be merged.)
#
# Verified in-sandbox on Python 3.10 / Ubuntu 22.04. Versions should match
# on Windows unless noted.
#
# ============================================================================
# CRITICAL VERSION-PIN FINDING — read before installing
# ============================================================================
# robosuite 1.5.2's OSC_POSE controller (controllers/parts/controller.py,
# `update()`) calls `mujoco.mj_fullM(model, mass_matrix, self.sim.data.qM)`.
# Newer MuJoCo python bindings removed the `MjData.qM` attribute (confirmed
# by direct introspection: `dir(mujoco.MjData())` has no `qM` on mujoco
# 3.11.0, but does on mujoco 3.3.0). robosuite's package metadata only
# requires `mujoco>=3.3.0`, which does NOT protect against pip resolving a
# newer, incompatible mujoco — this is a real, reproduced failure
# (`AttributeError: 'MjData' object has no attribute 'qM'`) hit and fixed
# while building environment.py, not a hypothetical.
#
# This repo's OTHER (older) requirements.txt pins mujoco==3.11.0 for the
# original raw-MuJoCo-XML pipeline (pick_and_place_flip.py, manipulation.py,
# etc.) — that version directly conflicts with what robosuite 1.5.2 needs.
# Use a SEPARATE virtual environment for this thesis pipeline:
#
#   python -m venv .venv_thesis
#   .venv_thesis\Scripts\activate        (Windows)
#   pip install -r requirements_thesis.txt
#
# Do not `pip install -r requirements.txt` and `-r requirements_thesis.txt`
# into the same environment — the two pin incompatible mujoco versions on
# purpose, because they're incompatible in practice, not by accident.
# ============================================================================
